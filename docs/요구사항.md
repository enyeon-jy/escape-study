# 요구사항: 시험범위에 갇혔다

## 배경
한양여대 소프트웨어융합과 2학년이 해커톤 대주제 "내 전공 현장을 바꾸는 AI", 트랙1 세부 주제 "공부·개발 도우미"로 혼자 참가한다.
제작자는 주말마다 방탈출 카페에서 일하는데, 손님들이 처음 보는 문제 앞에서도 1시간 내내 몰입하고, 스스로 단서를 찾아 푼 내용은 끝나고 나서도 오래 기억하는 모습을 봐 왔다.
반면 시험공부는 강의자료를 읽고 정리하는 방식이 대부분이라, 같은 시간을 써도 몰입감이 낮고 기억에 남는 정도가 다르다.
그래서 방탈출의 몰입감과 긴장감 있는 단서를 시험공부에 가져오고 싶었다.
다만 재미만으로는 그 순간에만 기억에 남을 것 같아서, 게임이 끝나면 재미 요소를 뺀 복습 단계로 넘어가 스스로 떠올리게 만드는 흐름으로 설계했다.

## 목적
강의자료를 넣으면, 그 내용을 긴장감 있는 단서 속에 숨긴 방탈출 게임을 만들어 주고, 탈출 후에는 복습 모드로 같은 개념을 다시 풀게 하는 웹 서비스.
확인하고 싶은 것: 학생이 탈출 후 복습 모드까지 이어서 하는지.

## 사용자
강의자료(PDF)로 시험공부를 하는 대학생. 휴대폰과 노트북 둘 다 사용.

## 흐름과 화면 (4개)
1. 시작·자료 넣기 화면
   - 글 직접 붙여넣기만 지원. PDF 올리기는 만들지 않는다. 입력칸 안내 문구: "강의자료 PDF를 열어 Ctrl+A, Ctrl+C로 복사해서 붙여넣으세요"
   - 붙여넣는 자료는 최대 8,000자까지만 사용하고, 넘으면 잘라서 쓴다 (설정값)
   - 과목 이름 입력
   - 테마 선택 카드 3개: 공포 / 이세계 탈출 / 추리
   - 난이도 선택: 쉬움 / 보통 / 어려움
   - 게임 길이 선택: 빠른 탈출(방 3개) / 전체 범위 탈출(자료 양에 맞춰)
   - "놀람 주의: 실패하면 교수님이 나타납니다" 켜기/끄기 스위치
   - "예시 자료로 해 보기" 버튼 (처음 온 사람도 바로 해 볼 수 있게)
   - "입장하기" 버튼, AI가 방을 만드는 동안 로딩 연출
   - 저장된 진행 상황이 있으면 "이어하기" 버튼
2. 방탈출 화면 (탐색형)
   - 방을 순서대로 진행. 방 개수는 아래 "게임 길이" 참고
   - 1인칭 탐색: 방 하나는 벽 3면(왼쪽·앞·오른쪽). 화면 양옆 ← → 화살표로 고개를 돌리듯 이동(부드러운 전환). 앞 벽에는 출구 문과 최종 자물쇠
   - 큰 물건(책상, 책장 등)을 누르면 클로즈업 화면이 되고, 그 안의 작은 물건(서랍, 노트, 컵 등)을 또 누를 수 있다. ↓ 버튼으로 방 전체로 돌아온다. 확대 화면은 방마다 2~3개
   - 물건을 누르면 단서 조각이나 아이템이 나오거나 "아무것도 없다"가 나온다
   - 아이템(열쇠, 메모, 카드)은 화면 아래 "가방"에 들어간다. 가방에서 아이템을 고른 뒤 잠긴 곳(서랍, 상자)을 누르면 열린다. 아이템은 방마다 열쇠 1개 정도로 단순하게
   - 찾은 단서는 "단서 수첩"에 쌓인다. 수첩(현재 방 단서만)과 가방(아이템)은 구분해서 보여 준다
   - 물건에 마우스를 올리면 살짝 빛나고, 이미 조사한 물건은 표시한다
   - 세계관: "시험 전날 밤 도서관에서 잠들었다 깨어 보니 시험범위 속에 갇혔다. 아침 9시 시험 전에 탈출해야 한다" (테마에 맞게 말투만 바꿈)
   - 첫 방은 튜토리얼처럼 쉽게(조작법 안내 말풍선), 갈수록 어렵게, 마지막 방은 탈출구가 있는 최종 방
   - 방 그림(벽 3면)은 테마별 1세트만 만들고, 방마다 물건 배치·단서·아이템·자물쇠 종류만 바꾼다
   - 자물쇠는 입력칸에 타자 치는 방식이 아니라 손으로 조작한다. 자물쇠를 누르면 화면 가운데로 확대된다
     - 숫자 다이얼(바퀴 3~4개, 0~9), 알파벳 다이얼(A~Z, 영어 약자 정답용), 키패드 도어락(삑 소리, 틀리면 빨간불·맞으면 초록불), 방향 자물쇠(↑↓←→ 순서, 순서형 개념용)
     - 정답 종류(숫자, 영어 약자, 순서)에 따라 맞는 종류를 쓰고, AI가 방을 만들 때 JSON의 `lock.type`으로 종류도 정한다
     - 바퀴 딸깍, 틀리면 흔들림과 덜컥, 맞으면 고리가 튕겨 열리는 애니메이션. 소리는 파일 없이 Web Audio
     - 휴대폰에서는 손가락으로 위아래로 쓸어서 돌릴 수 있게. 정답 확인은 코드가 한다
   - 방마다 제한 시간 타이머(난이도별), 힌트 버튼(난이도별 횟수, 쓰면 횟수 기록)
   - 틀리면 자물쇠가 흔들림, 맞히면 열리고 다음 방으로
   - 정답 보기: 그 방의 힌트를 다 쓴 뒤에만 "정답 보기" 버튼이 나타난다. 누르면 정답과 "왜 그게 답인지" 짧은 설명(AI가 방과 함께 만듦)이 나오고, 확인하면 자물쇠가 열린다. 탈출 방 수에는 포함한다
   - 방 시간이 끝나면 탈출 실패 → 교수님 등장 연출
   - 단서 형식은 방마다 다르게: 엿들은 대화, 찢어진 일기장, 경고 쪽지, 유출된 기밀 문서, 수상한 문자 메시지, 녹음 파일 받아쓰기 등
3. 탈출 결과 화면
   - 성공/실패, 방별 시간을 합산한 전체 걸린 시간, 힌트 사용 수, "정답 열람 N회", 틀렸던 자물쇠
   - "다시 도전" / "이제 진짜 공부하기" 버튼
4. 복습 모드 화면
   - 게임 연출 없이, 이번 게임에서 조합했던 개념을 빈칸 문제와 짧은 설명으로 다시 풀기
   - 정답을 열람한 개념은 복습에서 맨 먼저 나온다
   - 틀린 문제는 맞힐 때까지 다시 나오기
   - 끝나면 "내일 한 번 더 풀면 오래 기억에 남아요" 안내

## 단서 조합 방식
- 진짜 단서 여러 개를 합쳐야 답이 나온다. 단서 하나만으로는 답이 나오지 않는다.
  - 예: "비밀번호는 그 계층의 번호다" + "데이터를 패킷으로 나눠 길을 찾아 주는 곳" → 네트워크 계층 = 3
- **정답 근거 규칙:** 단서 조합이 정답을 가리키되, 자료에서 배운 개념을 알아야 숫자나 단어로 이어지게 한다. 단서에 정답을 그대로 쓰지 않는다.
- 가짜 단서는 그럴듯하지만 답과 상관없어야 한다.

## 난이도 (숫자는 코드의 설정값으로 관리, 나중에 쉽게 조절)
| | 쉬움 | 보통 | 어려움 |
|---|---|---|---|
| 진짜 단서 | 2개 | 3개 | 3~4개 |
| 가짜 단서 | 없음 | 1개 | 2개 |
| 개념 표현 | 단서에 개념 이름이 직접 나옴 | 설명으로 돌려 말함 | 아주 간접적으로 |
| 방당 시간 | 10분 | 7분 | 5분 |
| 힌트 | 3번 | 2번 | 1번 |

## 게임 길이 (자료 양에 따라 자동)
- 의도: 자료가 짧으면 짧게, 많으면 게임처럼 길게 즐기면서 범위 전체를 공부하게 한다.
- 자료에서 뽑은 핵심 개념 수에 따라 방 개수를 정한다: 개념 2~3개당 방 1개, 최소 3개, 최대 8개 (기준은 코드의 설정값)
- "빠른 탈출"은 방 3개, "전체 범위 탈출"은 자료 양에 맞춰 3~8개
- 방이 늘어나도 기다리지 않게, 첫 방만 먼저 만들고 다음 방은 플레이하는 동안 미리 만들어 둔다
- 제한 시간은 방마다 따로(난이도별), 전체 기록은 결과 화면에서 합산
- 방을 지날수록 스토리가 이어지고, 마지막 방은 탈출구가 있는 최종 방으로 연출
- 진행 상황은 브라우저(localStorage)에 저장해, 새로고침하거나 나갔다 와도 "이어하기"가 된다. 서버 DB는 쓰지 않는다

## AI가 할 일과 코드가 할 일
- AI: 자료에서 외워야 할 핵심 개념 뽑기, 테마에 맞는 방 이름·상황·스토리, 물건별 단서(진짜/가짜), 조합 정답, 힌트, 교수님 대사, 복습 문제를 JSON으로 만들기
- 코드: 정답 비교(띄어쓰기·대소문자·단위 무시), 타이머, 힌트 횟수, 방 개수 계산, 결과 계산, 저장
  - AI가 채점까지 하면 틀릴 수 있어서 정답 확인은 코드로 함
- AI에게 지킬 규칙:
  - 강의자료에 없는 내용으로는 문제를 내지 않기
  - 정답은 숫자나 짧은 단어로만 (애매한 답 금지)
  - 정답 근거 규칙(위)을 지키기
  - 단서에 실제 사람(교수님, 학생, 유명인)은 등장시키지 않기. 등장인물은 가상 인물이나 의인화한 개념만
  - 긴장감 있고 자극적이어도 되지만 욕설·비하·잔인한 표현은 넣지 않기

## 비용 규칙 (중요)
- 제작자는 돈을 쓸 수 없다. 유료 서비스, 카드 등록, 유료 요금제가 필요한 것은 절대 쓰지 않고, 필요해 보이면 먼저 물어본다.
- Vercel은 무료(Hobby)만 사용한다.
- AI는 학교 FactChat 키로만 부르고, 학교 크레딧을 아낀다:
  - 한 번 만든 방은 브라우저에 저장해서, 다시 하기나 새로고침 때 AI를 다시 부르지 않는다
  - 붙여넣는 자료는 최대 글자 수(8,000자)로 자른다
  - 방 개수 최대 8개를 지킨다
  - AI 호출이 실패하면 무한 재시도하지 않고 1번만 다시 시도한 뒤 안내 문구를 보여 준다

## 테마
- 공포: 폐교된 학교 실험실. 빨간 조명, 깜빡이는 형광등 분위기. 단서 예: 경고 쪽지, 찢어진 실험 일지. 분위기 연출(피 흘러내림, 귀신 실루엣)까지 허용, 상처·신체 훼손 묘사는 금지
- 이세계 탈출: 판타지 세계. 보라·청록 빛, 마법진, 퀘스트 느낌. 단서 예: 봉인된 마법서, NPC의 귓속말
- 추리: 사건 현장 연구실. 흑백 + 노란 폴리스라인, 탐정 수첩 느낌. 단서 예: 유출된 기밀 문서, 자백 녹취록, 엿들은 대화
- 테마에 따라 화면 색·연출과 단서 형식·말투·물건 종류만 바뀌고, 문제는 항상 강의자료에서만

## 탈출 실패 연출: 교수님 등장
- 방 시간이 끝나면 화면이 깜깜해졌다가 교수님 캐릭터가 화면 가득 "뙇!" 하고 튀어나오며 화면이 흔들림
- 교수님은 실제 인물이 아니라 새로 디자인한 만화 캐릭터 (SVG): 안경, 출석부, 화난 표정
- 테마별로 모습만 살짝 다르게 (공포: 창백한 얼굴, 이세계: 마법사 모자, 추리: 탐정 모자)
- 대사는 틀린 개념과 연결 (예: "자네, 아직도 ○○을 모르나?")
- 놀람 주의 스위치를 끄면 갑자기 튀어나오지 않고 조용히 등장

## 화면 디자인: 진짜 방탈출 게임처럼
- 이미지 파일 없이 HTML, CSS, SVG로만
- 어두운 방탈출 카페 분위기, 조명이 깜빡이는 효과
- 타이머는 폭탄처럼 빨간 디지털 숫자
- 단서는 형식에 맞게 연출: 쪽지는 구겨진 종이, 기밀 문서는 도장과 검은 줄, 대화는 말풍선이 한 줄씩 타자 치듯, 문자는 휴대폰 화면
- 자물쇠는 방 안의 문/금고 모양 SVG, 맞히면 "철컥" 열리는 애니메이션
- 힌트 버튼은 손전등 모양
- 탈출 성공 화면은 문이 열리고 빛이 들어오는 연출, 기록은 게임 점수판처럼
- 복습 모드는 일부러 밝고 깔끔한 공부 화면으로 바꾸기 (재미 단계와 공부 단계가 눈으로 구분되게 하려는 의도)
- 휴대폰 세로 화면에서도 잘 보이게
- 기존 게임이나 캐릭터를 따라 하지 말고 전부 새로 디자인
- 나중에 교내 GPU(틸론)로 만든 테마별 배경 이미지를 넣을 예정. 지금은 CSS로 배경을 만들되, `public/backgrounds/공포.png` 같은 이미지 파일을 넣으면 바로 그 이미지로 바뀌도록 배경 자리를 만들어 둔다.

## AI 연결 (학교 FactChat, OpenAI 방식)
- 주소: https://factchat-cloud.mindlogic.ai/v1/gateway (호출 경로는 `/chat/completions`, 다르면 첫 호출에서 확인해 고친다. `OPENAI_BASE_URL`로 바꿀 수 있다)
- 키는 서버 쪽 환경변수 `OPENAI_API_KEY`에만. 화면 코드에 절대 쓰지 말 것
- 모델 ID는 환경변수 `OPENAI_MODEL`로 읽는다 (값은 제작자가 학교 플랫폼 모델 탭에서 확인해 `.env.local`과 Vercel에 직접 넣는다)
- AI는 Next.js API 라우트(`/api/generate`)에서만 부른다
- 방 생성 흐름
  - 1번 호출: 자료에서 핵심 개념과 복습 문제를 뽑는다 (빠른 탈출 3~5개, 전체 범위 3~20개)
  - 방마다 1번씩 호출: 개념을 방마다 고르게 나눠 방 내용(이름·상황·스토리·단서·자물쇠 종류와 정답·힌트·정답 설명·교수님 대사)을 만든다. 첫 방만 먼저, 나머지는 플레이 중에 미리 만든다
  - 물건 배치(벽·클로즈업·열쇠·잠긴 칸)는 AI가 아니라 코드가 정한다. 단서가 빠지거나 겹치지 않고 AI가 줄 JSON도 짧아진다
  - AI에 주는 규칙: 자료에 없는 내용 금지, 실제 인물 금지, 정답은 숫자·짧은 단어, 단서에 정답을 그대로 쓰지 않기, 욕설·비하·잔인 금지
- 코드가 하는 검사 (깨졌거나 어기면 서버가 딱 1번만 다시 요청, 그래도 실패하면 "방을 만드는 데 실패했어요. 다시 시도해 주세요")
  - JSON 형식, 글자 수, 진짜/가짜 단서 개수(난이도 설정값), 힌트 개수
  - 정답 종류와 자물쇠 종류가 맞는지 (숫자 정답에 알파벳 자물쇠 등)
  - 정답이 강의자료에 실제로 있는 값인지, 진짜 단서에 정답이 그대로 쓰여 있지 않은지
- 서버 함수에서도 자료 8,000자 제한, 방 개수 최대 8개, 호출 횟수 제한(IP당 10분 40번)을 지킨다
- "예시 자료로 해 보기"의 예시 글을 그대로 쓰면 AI를 부르지 않고 예시 방을 쓴다 (크레딧 절약)

## 배포와 저장소

## 만드는 순서 (이 순서를 지킬 것)
1. 첫 배포 + 탐색형 재설계 (AI 연결 없이 예시 데이터로) — 완료
2. 공포 테마 디자인과 애니메이션 + 1인칭 벽 탐색·가방·손으로 푸는 자물쇠 — 완료
3. AI 연결 (FactChat) + 정답 보기 (학생이 붙여넣은 진짜 강의자료로 방이 만들어져야 서비스의 핵심이 완성되므로 앞당김)
4. 교수님 등장 연출
5. 이세계·추리 테마

## 테마별 디자인 (6단계)
- 테마마다 벽 3면 그림, 소품, 색, 조명, 효과음·배경 소리, 글꼴, 단서 카드, 자물쇠 겉모습을 따로 만든다. 게임 구조와 데이터 형식은 그대로(components/themes/, lib/themes.ts)
- 공포: 폐교 실험실(금 간 타일, 핏방울, 붉은 손자국, 귀신 실루엣). 귀신은 남은 시간이 줄수록 자주, "놀람 주의"를 끄면 안 나옴
- 추리: 탐정 사무실(세피아, 사건 보드, 비 오는 창, 빗소리)
- 이세계: 떠 있는 돌 조각과 우주, 오로라, 룬 마법 다이얼, 반짝이는 입자
- 글꼴은 무료 웹폰트(Google Fonts), 그림은 SVG·CSS, 소리는 Web Audio. 움직임 줄이기 설정이면 피·귀신·입자·비 애니메이션을 멈춘다
