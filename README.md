# 시험범위에 갇혔다 (escape-study)

> 강의자료를 붙여넣으면 AI가 **방탈출 게임**(방·단서·자물쇠·이야기)을 만들어 주고, 풀면서 개념을 꺼내 보게 한 뒤, **복습 모드**로 이어지는 시험공부 웹 서비스.

👉 **배포 주소: https://escape-study-alpha.vercel.app** (Vercel 무료 Hobby, `main`에 push하면 자동 배포)

## 1. 한 줄 소개와 30초 사용법

1. 배포 주소를 열고 **시작하기**(잠긴 자물쇠가 풀리며 문이 열림)를 누른다. 이전 기록이 있으면 **이어하기**도 나온다.
2. 설정을 한 화면에 하나씩 고른다: ① 강의자료 붙여넣기 ② 과목 이름 ③ 테마 ④ 난이도 ⑤ 게임 길이 ⑥ 놀람 주의 켜기/끄기. 처음이라면 ①에서 **예시 자료로 해 보기**를 누른다(AI를 부르지 않는다).
3. **입장하기** → 방을 둘러보고(← → 로 벽 3면), 물건을 눌러 단서를 모아 **손으로 돌리는 자물쇠**를 푼다.
4. 모든 방을 탈출하면 결과 화면, **이제 진짜 공부하기**를 누르면 복습 모드로 넘어간다.

## 2. 문제 정의 (20점)

- **누가:** 강의자료(PDF 등)로 시험공부를 하는 대학생. 휴대폰과 노트북을 둘 다 쓴다.
- **언제:** 시험 직전에 짧은 시간 안에 범위 전체를 훑어야 할 때.
- **무엇이 불편한가:**
  - 자료를 읽고 정리하는 방식이 대부분이라 읽는 동안은 알 것 같아도 **스스로 떠올려 보는 과정이 없어 기억에 남는 정도가 낮다.**
  - 혼자 문제를 만들어 풀기는 번거롭고 **지루해서** 오래 이어 가기 어렵다.
- **제작 동기:** 제작자는 방탈출 카페에서 일하며, 손님들이 처음 보는 문제 앞에서도 오래 몰입하고 스스로 찾아 푼 내용을 오래 기억하는 모습을 봐 왔다. 이 몰입을 시험공부에 가져오되, 재미만 남지 않도록 **게임 뒤에 재미 요소를 뺀 복습 단계**를 붙였다. (이 관찰은 제작자의 경험이며 효과를 검증한 것은 아니다.)
- **학습 원리(참고):** 읽기만 하는 것보다 스스로 떠올려 보는 시험·인출 연습이 장기 기억에 유리하다는 "시험 효과(testing effect)" 연구가 있다(Roediger & Karpicke, 2006). 이 서비스의 자물쇠 풀기와 복습 빈칸 문제는 이 원리를 따른 설계이고, 서비스 자체의 효과는 아직 측정하지 않았다.

## 3. 해결 방법

강의자료 붙여넣기 → AI가 핵심 개념을 뽑고 방을 만듦 → 단서를 조합해 자물쇠를 풂(인출 연습) → 결과 → 복습 모드.

| 구분 | 구현된 기능 |
|---|---|
| 입력 | 글 붙여넣기만 지원(최대 8,000자, 넘으면 잘라서 사용), 과목 이름, "예시 자료로 해 보기" |
| 게임 구성 | 빠른 탈출(방 3개) / 전체 범위 탈출(개념 수에 따라 방 3~8개), 난이도 쉬움·보통·어려움 |
| 탐색 | 1인칭 벽 3면 돌아보기, 큰 물건 클로즈업, 작은 물건 조사, 단서 수첩, 가방(열쇠 등 아이템으로 잠긴 칸 열기), 방마다 타이머와 힌트 |
| 단서 | 진짜 단서를 여러 개 조합해야 답이 나옴, 가짜 단서(보통 1개·어려움 2개). 쪽지·일기·문서·문자·대화·녹음 받아쓰기 모양 |
| 자물쇠 | 숫자 다이얼, 알파벳 다이얼, 키패드, 방향 자물쇠. 위아래로 쓸어서 돌림(휴대폰 지원), 소리는 Web Audio |
| 코드 자물쇠 | 프로그래밍 과목(파이썬·자바스크립트)이면 방 하나는 모니터의 코드를 읽고 **실행 결과**를 맞힌다 |
| 정답 공개 | 그 방의 힌트를 다 쓴 뒤에만 "정답 보기"가 나오고, 정답과 이유가 보인다. 결과에 "정답 열람 N회"로 기록된다 |
| 테마·이야기 | 공포("낙제 감독관"), 추리("시험지 유출 사건"), 이세계("망각의 마왕"). 테마마다 방 공간 4개(예: 공포는 교실→과학실→복도→보일러실)와 그림·소리·글꼴·단서 모양·자물쇠 모양이 다름. AI가 개념을 그 공간의 장치로 바꿔 쓰고, 탈출 직후 한 줄 정리와 마지막 방 결말이 나온다 |
| 결과 | 성공 여부, 방별 시간 합산, 힌트 수, 정답 열람 수, 틀렸던 자물쇠, 결말과 방별 정리. 성공 화면에 문틈 빛 이미지([6장](#6-교내-gpu틸론-활용-15점)) |
| 복습 | 밝고 단순한 공부 화면에서 빈칸 문제로 개념을 다시 풂. 정답을 열람한 개념이 먼저 나오고, 틀린 문제는 맞힐 때까지 다시 나온다. 끝나면 "내일 한 번 더 풀면 오래 기억에 남아요" 안내 |
| 이어하기 | 만든 방과 진행 상황을 브라우저(localStorage)에 저장해 새로고침 후에도 이어짐 |

## 4. AI 활용 (20점)

**(a) 서비스 안에서 AI가 하는 일** (학교 FactChat의 OpenAI 호환 API, 서버에서만 호출)
1. 강의자료에서 핵심 개념을 뽑고 복습용 빈칸 문제를 만든다(게임당 1번 호출).
2. 방마다 1번씩 호출해 방 이름·상황·이야기, 진짜/가짜 단서, 자물쇠 종류와 정답, 힌트, 정답 설명, 탈출 후 정리 한 줄, 실패 때의 대사, 마지막 방 결말을 JSON으로 만든다. 개념을 그 공간의 장치·사건으로 바꿔 쓰게 지시한다(예: "세 번 노크해야 열리는 문").
3. 코드 자물쇠 방에서는 짧은 코드(5~10줄)와 주변 단서를 만든다.

**(b) AI와 코드의 역할 분리**

| AI가 하는 것 | 코드가 하는 것 |
|---|---|
| 개념 추출, 방·단서·이야기·힌트 문장 생성 | **정답 판정**(띄어쓰기·대소문자·단위 무시), 타이머, 힌트 횟수, 방 개수 계산, 결과 계산, 저장 |
| 코드 자물쇠의 코드와 주변 단서 생성 | **코드를 실제로 실행해 정답 결정**(AI가 말한 값과 다르면 실행 결과를 정답으로 쓰고 힌트·설명도 교체) |
| — | 물건 배치(벽·클로즈업·열쇠·잠긴 칸), JSON 형식·글자 수·단서 개수·힌트 개수 검사 |

**(c) 자료에 없는 내용을 지어내지 않도록 한 안전장치** (`lib/validate.ts`, `lib/validateCode.ts`, `lib/server/prompts.ts`)
- 지시문에 "자료에 있는 내용만, 실제 인물 금지, 정답은 숫자·짧은 단어, 단서에 정답을 그대로 쓰지 않기"를 넣는다.
- 방마다 AI가 **강의자료에서 글자 그대로 베낀 근거 문장**(`sourceQuotes`)을 내야 하고, 코드가 그 문장이 실제 자료에 있는지 확인한다. 없으면 그 응답을 버린다.
- 정답 종류와 자물쇠 종류가 맞는지(숫자 정답에 알파벳 자물쇠 등), 진짜 단서에 정답이 그대로 적혀 있지 않은지 검사한다. 복습 문제도 정답이 자료에 실제로 있어야 쓴다.
- 검사에 실패하면 서버가 **딱 1번만** 다시 요청하고, 그래도 안 되면 안내 문구를 보여 준다(무한 재시도 없음). 자료 8,000자, 방 최대 8개, IP당 10분 40번 호출 제한으로 학교 크레딧을 아낀다. 한 번 만든 방은 브라우저에 저장해 다시 하기 때 AI를 다시 부르지 않는다.
- 코드 자물쇠의 코드는 줄 수·길이·위험한 말(`import`, 네트워크, 파일 등)을 검사한 뒤 브라우저에서 실행하고, 시간이 넘으면 강제 종료한다. 실행이 안 되거나 정답 형식이 맞지 않으면 그 문제를 버리고 **일반 방으로 대체**한다.

## 5. 구현·배포 (30점)

| 항목 | 내용 |
|---|---|
| 기술 | Next.js 16(App Router), React 19, TypeScript. 별도 UI·게임 라이브러리 없이 SVG·CSS·Web Audio로 그림과 소리를 만듦(그림 파일 없이) |
| 배포 | Vercel 무료 Hobby, GitHub `main`에 push하면 자동 배포 |
| AI 호출 | `app/api/generate/route.ts`(서버)에서만. 키는 화면 코드에 없음 |
| 저장 | **Supabase(무료 요금제)에 게임 설정과 플레이 기록만 저장.** `games`: 과목명·테마·난이도·게임 길이·방 JSON, `play_logs`: 성공 여부·걸린 시간·힌트 수·정답 열람 수·복습 완료 여부. **강의자료 원문, 이름·이메일, IP는 저장하지 않는다.** 저장은 서버 함수(`/api/save`)에서만, 테이블은 RLS를 켜 공개 키로는 접근할 수 없다. 저장이 실패해도 게임은 그대로 진행된다. 테이블 생성 SQL은 [`supabase/schema.sql`](supabase/schema.sql), 설정 방법은 [docs/supabase.md](docs/supabase.md) |
| 코드 실행 | 자바스크립트: 제한된 Web Worker. 파이썬: 오픈소스 Pyodide(브라우저용 파이썬, jsDelivr CDN에서 내려받음) |
| 점검용 페이지 | `/lock-demo`(자물쇠 4종), `/code-demo`(코드 실행기), `/theme-preview`(테마 그림) |

**환경변수 이름** (값은 `.env.local`과 Vercel 환경변수에만 넣고, 저장소에는 올리지 않는다. 목록: `.env.example`)

| 이름 | 용도 |
|---|---|
| `OPENAI_API_KEY` | 학교 FactChat 키 (서버 전용) |
| `OPENAI_MODEL` | 사용할 모델 ID |
| `OPENAI_BASE_URL` | (선택) 기본값 `https://factchat-cloud.mindlogic.ai/v1/gateway` |
| `AI_TIMEOUT_MS` | (선택) AI 호출 제한 시간, 기본 40000 |
| `SUPABASE_URL` | Supabase 프로젝트 주소 (서버 전용) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 서버용 비밀 키 (서버 전용) |

**로컬 실행**
```bash
npm install
npm run dev      # http://localhost:3000
```
환경변수가 없어도 "예시 자료로 해 보기"는 동작한다(AI·Supabase 없이). 난이도·방 개수·자료 글자 수 같은 숫자는 `lib/config.ts`에서 조절한다.

**접근성·안전 (실제로 한 것만)**
- "움직임 줄이기"(`prefers-reduced-motion`)를 켜면 핏방울·귀신·입자·비·오로라 같은 애니메이션을 멈추고 귀신 실루엣은 나오지 않으며, 탈출 성공 이미지는 바로 보인다.
- "놀람 주의"를 끄면 공포 테마의 귀신 실루엣이 나오지 않는다.
- 빛이 빠르게 번쩍이는 효과는 쓰지 않고, 깜빡임은 느린 밝기 변화만 쓴다.
- 물건은 키보드(Tab, Enter)로도 누를 수 있고, 모든 창은 ✕ 버튼·바깥 클릭·Esc로 닫힌다. 휴대폰 세로 화면 폭으로 화면을 점검했다. (스크린 리더 전문 점검은 하지 않았다.)

## 6. 교내 GPU(틸론) 활용 (15점)

- 교내 GPU 서버의 **JupyterLab**에서 **SDXL-Turbo**로 탈출 성공 화면에 쓰는 **"문틈으로 빛이 새는 문" 이미지**를 생성했다.
- 방법: 코드로 문의 **밑그림**을 만들고, 프롬프트를 더해 **img2img**로 생성했다.
- 생성한 파일을 내려받아 [`public/images/escape-door.png`](public/images/escape-door.png)로 넣었고, **모든 테마의 탈출 성공 화면**에서 어둡게 시작해 1~2초에 걸쳐 밝아지게 보여 준다. 이미지 뒤의 은은한 빛 색은 테마마다 다르다. 화면 하단에 "이미지: 틸론 GPU SDXL-Turbo로 생성"이라고 출처를 표시했다.
- **생성 과정과 증빙 캡처(JupyterLab 파일 트리, 실제 서비스 화면): [docs/tilon-gpu.md](docs/tilon-gpu.md)**
- 이미지 생성은 서버 GPU에서 미리 해 둔 것이고, 서비스가 실행 중에 GPU를 부르지는 않는다. 생성에 쓴 노트북·스크립트는 이 저장소에 포함하지 않았다. 테마별 배경 이미지를 같은 방식으로 넣을 수 있게 `public/backgrounds/`(공포.png, 이세계.png, 추리.png) 자리를 만들어 두었으나, 아직 파일은 없다.

## 7. 개발 과정과 기록

- **Claude Code**로 기능을 하나씩 나눠 개발했고, 기능 하나가 끝날 때마다 알아보기 쉬운 메시지로 커밋했다. 흐름은 커밋 기록(`git log`)에서 볼 수 있다: 첫 배포와 탐색형 재설계 → 공포 테마와 손으로 푸는 자물쇠 → AI 연결과 정답 보기 → 테마 3종 디자인 → 코드 자물쇠 → 시작 화면 개편 → Supabase 저장 → 세계관과 공간 → 탈출 성공 이미지.
- **[docs/요구사항.md](docs/요구사항.md)**: 문제 배경, 화면 흐름, 난이도 표, AI와 코드의 역할, 비용 규칙, 테마·세계관·공간 목록 등 기획 전체. **[docs/supabase.md](docs/supabase.md)**: Supabase 설정 단계별 안내. **[CLAUDE.md](CLAUDE.md)**: AI 개발 도구에 준 프로젝트 규칙(키는 환경변수만, 정답 확인은 코드로, 무료 서비스만, 개인정보 저장 금지 등).
- 개발 중 화면과 흐름은 임시 점검 스크립트로 확인했다. 이 스크립트와 자동 테스트 코드는 저장소에 포함되어 있지 않다.

## 8. 확장 계획과 한계 (15점)

**계획 (아직 구현되지 않음)**
- 다른 과목 자료 지원 확대: 코드 자물쇠를 SQL·자바 등으로 넓히기, 수식·표가 많은 자료 대응
- 공유 링크: 만든 방을 친구와 함께 풀기
- 약한 개념 반복 출제: 지금은 한 번의 복습 안에서 틀린 문제만 반복하고, 세션을 넘어 약한 개념을 기억해 다시 내지는 않는다
- PDF 직접 업로드(지금은 복사해서 붙여넣기만 지원)
- 테마별 배경 이미지를 교내 GPU로 추가 생성

**현재 한계 (솔직하게)**
- **실제 학생 대상 사용자 테스트를 하지 않았다.** 재미·몰입이나 학습 효과가 있는지는 검증하지 못했다.
- **AI가 만든 방의 품질에 편차가 있을 수 있다.** 코드 검사로 형식·근거 문장·정답 노출은 걸러내지만, 단서가 어색하거나 문제가 너무 쉽거나 어려운 경우는 사람이 일일이 확인하지 못했다. 검사 탈락 시 1번만 재시도하므로 가끔 "방을 만드는 데 실패했어요"가 나올 수 있다.
- **교수님 등장 연출은 미완성이다.** 실패하면 세계관 인물의 대사를 글로 보여 줄 뿐, 화면 가득 튀어나오는 캐릭터 연출은 아직 없다. "놀람 주의" 스위치는 현재 공포 테마의 귀신 실루엣 여부에만 영향을 준다.
- 파이썬 코드 방은 첫 실행에 실행 도구를 내려받는다(개발 중 측정 1회에서 약 9초). 코드 자물쇠는 파이썬·자바스크립트만 지원하고, 실행에 실패하면 일반 방으로 바뀐다.
- 방 생성·AI 호출 횟수 제한은 서버 인스턴스별 간단한 방식이다. 방 내용 일부(탈출 후 정리, 결말)는 AI가 못 만들면 기본 문장으로 대체된다.
- 자료는 텍스트 붙여넣기만 가능하고 8,000자까지만 사용한다.
- 예시 자료로 하는 게임은 AI 없이 방 4개(코드 방 포함)로 고정이다.
